# M152 ExternalString 연구 — 공개 결과 근거 요약

2026-10-02 편집 기준. 대상은 Chrome 152.0.7977.64, 이슈 532204454다. 이 문서는 공개 가능한 실행 결과와 수치의 해석 범위를 정리한다.

## 자료와 대조 범위

제공된 연구 묶음에는 연구보고서, 일부 체크포인트, 진행 기록과 집계 자료가 포함된다. 해시 목록의 파일 무결성은 확인했지만, 이번 편집에서 원본 PoC를 다시 실행하지는 않았다. 파일 무결성과 실험 재현은 서로 다른 확인이다.

## 연구 시작점, 실행 전제와 경계

연구는 M152의 `ExternalString::DisposeResource`와 수정 패치를 대조해 두 번의 handle 해석과 가능한 `h1/h2` interleaving을 분석하는 데서 시작했다. 이후 공식 `regress-532204454.js`가 `--sandbox-testing`, `Sandbox.MemoryView`와 Worker로 handle-field race를 재현하는 방식을 대조하고 d8에서 UAF 판정 기준을 세웠다.

실행에서 그 interleaving을 만들려면 `ExternalString.resource_` 핸들을 경쟁적으로 바꿀 수 있어야 한다. 회귀 테스트에서는 harness가 cage 내부 쓰기를 제공하고, 전체 체인에서는 별도 in-cage primitive가 같은 역할을 수행한다. 이는 issue532의 실행·체인화 전제이며, 초기 취약점 분석이 이미 완성된 선행 능력에서 시작했다는 뜻은 아니다. 별도 in-cage primitive 자체의 원리와 개발 과정은 이 자료의 범위 밖이다.

V8 Sandbox 메모리 경계와 Chrome renderer의 OS process sandbox는 별개의 방어 계층이다. 공개 결과는 전자의 경계를 넘는 네이티브 객체 UAF를 뒷받침하지만, 후자의 escape를 입증하지 않는다.

## 초기 관측

공유 호스트 약 950회에서는 UAF 판정이 관측되지 않았고, 분리한 ASan d8 조건에서는 150회 중 11회가 기록됐다. 판정은 남은 `h2`를 통한 후속 사용이 `ExternalString::DisposeResource`의 `heap-use-after-free`로 보고되고, allocation·free·use가 같은 해제 주소로 연결되며 그 주소가 V8 cage 밖의 네이티브 힙임을 확인한 경우다. 단순 크래시나 주소 잔존은 포함하지 않았다. `11/150`은 약 7.33%이며 다른 환경의 표본과 합치거나 브라우저 전체 완료율로 바꾸지 않았다.

## 성공률 안정화 과정

연구는 환경 분리, 의미 있는 winner 판정, race window 안의 비동기 작업·로깅 제거, dangling holder와 allocator 상태를 만드는 객체의 수명 분리, 정확한 주소 재사용 측정, 연속해서 필요한 레이스 수 축소, 시도별 새 렌더러 사용 순으로 진행됐다.

단일 관측값 `p = 11/150`을 독립·동일확률 모형에 넣으면 `p² ≈ 1/186`, `p³ ≈ 1/2,536`, `p⁴ ≈ 1/34,578`, `p⁵ ≈ 1/471,512`, `p⁶ ≈ 1/6,429,711`이다. 이는 초기 설계의 복잡도를 비교하는 이론값이며 측정된 브라우저 완주율이 아니다.

## 조건부 판정과 전체 시행

특정 후반 단계의 적격 분기는 `5/5`, 같은 실험군에서 upstream race를 포함한 전체 완료 출력은 `2/60`이었다. 조건부 `5/5`를 전체 성공률 100%로 사용할 수 없다. 후반 반복 검증에는 실행 묶음 단위에서 실패가 관측되지 않았다고 기록되어 있지만, 정확한 최종 분모가 확인되지 않아 확정 `N/N`이나 통계적 신뢰구간은 제시하지 않는다.

## 파일 읽기 결과와 권한

작성자는 자신이 관리한 별도 원격 검증 환경에서도 `/etc/hosts` 읽기까지 완료했다고 확인했다. 이 후속 결과는 로컬 실험 수치와 별도로 다룬다. 여기서 원격은 실행 위치를 뜻하며, 일반적인 RCE나 Chrome OS sandbox escape 판정으로 사용하지 않는다.

보고서는 디버거나 상위 프로세스의 메모리 관측에 의존하지 않은 로컬 `/etc/hosts` 읽기 사례를 기록한다. 로컬의 비활성 프로세스 sandbox와 사전 부여 권한은 실행 전제다. 결과는 기존 권한에서의 체인 완료를 보여 주며 새 OS 권한 획득을 의미하지 않는다.

## 공개 범위

공개 글은 빌드 전용 주소, 전체 PoC와 제어 흐름 세부를 제외한다. 원인 코드, `h1/h2` 상태 변화, 객체 크기 클래스, 측정값과 패치 불변식은 재검토 가능한 범위로 남긴다.

동봉된 `evidence-summary.SHA256SUMS`는 한국어·영문 요약 파일 자체의 해시다. 원본 실험 결과가 재현됐다는 인증을 의미하지 않는다.
