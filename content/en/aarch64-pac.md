### Pointer Authentication Code

This is a security technique added in ARMv8.3 that guarantees the integrity of the correct memory address by signing the pointer.  
   
Vulnerabilities in most stacks, including amd64, are achieved by modifying \[ret\].   
The most representative example is rop, which is a vulnerability that changes the call flow of the binary.  
Based on aarch64, the vulnerability affects call flow by calling other functions using the assembly language called br.  
To prevent this, PAC is a technology that checks the integrity of the pointer address and prevents the call flow from being changed, thereby ensuring that the binary is executed as intended.  
 

* * *

![](/assets/images/tistory/tistory-176b1d39004b/001.png)

When creating a PAC, three values are required: Key, Context, and Pointer.  
   
Keys play the role of generating authentication codes and are classified according to pointer type and privileged level.

-Instruction key
    - APIAKey, APIBKey
    - Used when applying PAC to pointers related to control flow
-Data key
    - APDAKey, APDBKey
    - Used when applying PAC to general data pointers (object pointers, general variable pointers, etc.)
- Generic key
    -APGAKey
    - Used when applying PAC to a pointer that can be commonly used throughout the system

   
If you look at each key, you can see that the key composition is the same, but it is divided into A and B.  
A stands for user mode and B stands for kernel mode.  
   
A 128-bit key is defined, and the PAC value is generated by calculating it through an algorithm.  
   
The algorithm used at this time is an algorithm called QARMA, which is a symmetic block cipher algorithm.  
   
   
Let's look at the system registers used with key registers.  
 

#### Key register

For each of the five keys mentioned above, there is a register divided into low and high bits.

![](/assets/images/tistory/tistory-176b1d39004b/002.png)

#### SCR (Secure Configuration Register)

Add API bit and APK bit that are accessible only in EL3.  
API: When an instruction fault occurs, it is trapped by EL3.  
APK: Trapped with EL3 when key register access occurs.  
And the corresponding situations are recorded in ESR\_ELx.EC.  
It is a register that plays the role of configuring security policies and controlling interactions as a whole.  
 

#### SCTLR (System Control Register)

It is used to control the operating mode of the system and is set to the default value when booting.  
This may be changed later when setting the cache, endian mode, etc.  
 

#### ESR (Exception Syndrome Register)

When an exception occurs, detailed information about the exception is provided.

After PAC is applied, an instrucion is added to the prologue and epilogue of each function.  
 

![](/assets/images/tistory/tistory-176b1d39004b/003.png)![](/assets/images/tistory/tistory-176b1d39004b/004.png)

The left side is before PAC application, and the right side is after application.  
 

```
pacibsp

...

autibsp
```

You can see that the above command has been added.  
   
   
First, let's look at the basic commands starting with pac\* and aut\*.  
pac\*: This is a command used to insert a keyed MAC and places the calculation result in the top byte of the Target Pointer Address.  
aut\*: Used to verify the Keyed MAC in the Pointer Address.  
   
At this time, if the Keyed MAC verification result is false, an abnormal termination occurs, like when the canary is tampered with.  
   
   
If we look again at the above commands, pacibsp and autibsp, they are structured to generate a PAC value using the sp value as context.  
To be precise, the PAC of lr is calculated using Instruction key B, and the context at this time means that the value of the sp register will be used.  
Conversely, autibsp is also a step to verify the PAC created through the above process.  
Looking at the addresses created in this way, they are as follows.

![](/assets/images/tistory/tistory-176b1d39004b/005.png)

If you look at the address 0x5500800088, you can see that there is a 0x78 in front of the address.  
This value is the PAC value.
